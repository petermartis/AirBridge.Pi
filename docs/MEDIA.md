# Native HDMI media add-on
## Scope and acceptance
The approved optional add-on provides native local-file HDMI media playback. It does not replace firmware, upgrade the kernel/wireless stack, change network topology or activate touch. Read [hardware](HARDWARE.md), [development](DEVELOPMENT.md), [status](STATUS.md) and [recovery](TROUBLESHOOTING.md) first.
Preserve OpenWrt **25.12.6**, Linux **6.12.112**, `bcm27xx/bcm2712`, ARM64 musl and kernel ABI **`294a8151df6d94c4f262106e0654471f`**; the signed r6 MA86XH driver/startup repair-on/tracing-off, WPA3/80 MHz configuration and LCD's 1 MHz/rotation 90/320×240 remain invariants.
**Real hardware 4K30 playback and a measured presentation improvement are demonstrated, not feature-film-duration or 4K60 acceptance.** The user confirmed moving 4K HDMI video/audio, authenticated LuCI, and subsequently a smooth clean 10-bit grid/moving box with no flashes. The diagonal sweep was verified against native reference frames as source animation, not output corruption. Native API queue/pause/seek/resume passed; traversal was rejected.
Main/Main10 3840×2160@30 samples reported hardware `drm` with `rpi4_8`/`rpi4_10`. Earlier short shader-rendering trials had VO drops despite zero decoder drops. The corrected plane mapping below produced **Main10 total2/steady+0 VO drops; Main total1/steady+0**, retaining startup drops honestly. Physical 10-bit pattern observation supersedes the earlier lack of separate Main10 picture confirmation; arbitrary Main10 files and sustained full-length playback still require testing.

## Reproducible host build
Use an isolated Linux workspace and a **copy** of the exact prepared SDK/toolchain, never a production SDK or router root. Host requirements include modern Python 3, matching `aarch64-openwrt-linux-musl` binutils/compiler, Meson/Ninja, Make, CMake, pkg-config, source-specific autotools and `qemu-aarch64`. libplacebo requires **native host `python3-glad`**, not a cross-target-only installation.
`build.py` expects `$MEDIA_WORK/toolchain`, defaults to `/work`, and writes downloads/src/build/prefix/stamps there. Existing stamps/Meson directories reuse prior options: changed configuration requires a fresh reviewed workspace, not an assumption that rerunning reconfigured it.
```sh
export MEDIA_WORK=/work
export AIRBRIDGE_REPO=/opt/airbridge-repo
python3 "$AIRBRIDGE_REPO/media/engine/build.py" --fetch
python3 "$AIRBRIDGE_REPO/media/engine/build.py"
```
First-use fetch hashes are integrity pins, **not independent upstream signature verification**; retain/review the lock and archives. Later builds refuse changed URLs/hashes. The observed runtime is mpv **0.42.0**, Raspberry Pi FFmpeg **8.1.2**, Mesa **25.0.7**, approximately **48.8 MB** staged before dependency/install overhead. QEMU verified **23 required decoders**; it cannot test V4L2/GPU/HDMI/realtime behavior.
FFmpeg networking is disabled, V4L2-request/SAND enabled; mpv enables DRM/GBM/EGL/OpenGL/ALSA but disables Lua, JavaScript and C plugins. Launcher `AIRBRIDGE_MEDIA_MPV_SCRIPTING=0`/`AIRBRIDGE_MEDIA_MPV_LUA=0` must match. Scripting-disabled mpv rejects some script-specific flags: do not append incompatible flags as an assumed hardening fix.

Deployment remains a separately authorized device action, not a host-test side effect. Preserve private backups, Ethernet recovery, exact hashes/dependency metadata and previous known-good packages. Authenticate privately with strict host-key checks; never dump wireless/hostapd configuration, keys or raw backup images.

New package defaults remain `enabled=0`, `root=/mnt/media`, `nice=5`; the validated deployed device was explicitly enabled. UCI `nice` accepts **0..19**, applies to the **player only**, and invalid values fall back to 5. No global CPU governor/scheduler changes are made.

The final reboot verified these settings on the current device. On another installation coordinate any reboot separately, then repeat read-only startup checks; do not infer reboot success merely from enabled symlinks.
Current reviewed config retains `vo=gpu`, built-in `profile=fast`, DRM/OpenGL, `drm-mode=3840x2160@30` and ALSA, with the **corrected DRM PRIME mapping** below. This rendering preset is distinct from controller `quality4k`/`balanced`/`quiet`.

### Software-decoded picture cleanup (controller package r7)
Software-decoded files (H.264, VP9, AV1 under `balanced`/`quiet`) are drawn by the GPU onto the 4K overlay surface; the video plane is disabled. A 2026-11-15 report of tiny green noise in dark scenes of a 720×576 H.264 film was traced by dumping the real scanout framebuffer: the specks are scattered chroma samples in the source's near-black areas, reproduced unfiltered and enlarged 3.75× with dithering off. Alpha was 255 everywhere and the colour conversion matched a reference, so plane blending and matrix errors were ruled out.
Package r7 therefore adds two settings after `profile=fast`: `dither=fruit` and `glsl-shaders=/etc/airbridge-media/dark-chroma.glsl`. The fixed packaged shader runs at source chroma resolution, **only for standard-definition sources** (luma width up to 800), and, for dark pixels only, replaces a chroma sample with the mean of similar nearby samples; luma, mid-tones and real colour edges are untouched. On the paused test frame green-dominant dark pixels fell from 0.55 % to 0.06 %, with zero added decoder/display drops in 15–20 s windows. `scale=spline36` and `scale=mitchell` were measured and **rejected**: 205 and 84 display drops in comparable windows. Keep bilinear scaling. An intermediate r6 applied the shader to every source and **regressed 1080p H.264**: 35–42 display drops in 7 s with the 49-sample window and 12–13 with a 12-sample one, against 0 without it. r7 skips the pass above SD. Dithering alone added 0–2 startup display drops (5 once in 16 runs) on the 1080p sample and none after the first two seconds. See the [record](../media/validation/cm5-20261115-dark-chroma.json).
Zero-copy hardware HEVC frames bypass the GPU renderer, so neither setting affects that path. On the TV the user still saw specks at 4K output with r7; they were gone once the same film was output at 1080p (below), where the player enlarges the picture far less. The shader is not a script, plugin or user-selectable file; do not add a shader option to the API.
### Output mode per file (controller package r10)
With software-decoded video drawn at 3840×2160 the user saw a damaged-looking single frame about once per second, more often in bright scenes, at both 30 Hz and 25 Hz; nothing flashed while paused. Player counters stayed at zero drops and a scanout watcher found no frame redrawn while the display hardware pointed at it (0 of 1,001 flips), so the drawn frames were complete. At **1920×1080 25 Hz** (74.25 MHz TMDS) the user reported a perfect picture; 1080p 50 Hz (148.5 MHz) was reported as very bad with distorted audio; the TV once failed to lock after a reload. Later the same day a 4K HDR HEVC film under `quality4k` flickered too. A cable and TV-port swap changed nothing and 1920×1080@120, which uses the same 297 MHz signal rate, was clean, so the link is not the cause; the fault follows a moving 3840×2160 picture and is **unresolved** (router 4K output path or the TV's 4K input). The TV's SCDC error counters were high even on clean pictures and are not evidence. HDR is not signalled either (8-bit RGB, no metadata).

The controller therefore chooses the display mode per file, because mpv reads `drm-mode` only when the video output opens:
- `quality4k`: sets `3840x2160@30` before loading; hardware-decode requirement unchanged.
- `balanced`/`quiet`: loads paused, reads the first real video track's frame rate, and uses 1080p at 23.98/24/25/29.97/30 Hz (50/60 fps content uses 25/30 Hz). If the open display has another mode it sets `drm-mode` and changes the DRM-unused `wid` option, which makes mpv close and reopen the output without reloading. It unpauses only after the file is loaded and the output is configured. If the matched mode cannot be opened it reloads once at `1920x1080@30`, then fails with `display output mode unavailable`.

r10 compares the mode the display **really** has open (`display-width`, `display-height`, `display-fps`) with the wanted one, for both profiles, and reopens it if they differ. r9 trusted the requested `drm-mode` option, but an output left open by the previous file keeps its old mode: a 4K film started right after a profile change landed on the 1080p output and showed a dark screen with sound.

Consequences: a 4K HEVC file played under Balanced is output at 1080p (use `quality4k` for 4K); the TV re-syncs when the mode changes between files; modes above 74.25 MHz are never selected for the software path. The earlier unconditional unpause right after `loadfile` could leave a file paused at 0:00 and was removed. Do not load with `vid=no` to hold the display closed: video-only files then end with "no audio or video data played" (r8, replaced the same day).

## LuCI and native API
Use existing authenticated LuCI **Services → AirBridge.Pi Media**, URL **`/cgi-bin/luci/admin/services/airbridge-media`** (view route `admin/services/airbridge-media`). There is no standalone server. Same-origin RPC uses **`airbridge.media`**; read ACL is status/browse/storage, write ACL play/pause/stop/seek/volume/tracks/queue/profile/remove/upload_begin/upload_cancel. Private upload coordination is excluded. No global UCI/filesystem/exec/wildcard grant is needed. Names and telemetry are DOM text, not HTML.
Every reply has `ok:boolean,error:string|null`; transport success alone is insufficient. `available` means private IPC answered, not physical playback. Unavailable status is `ok:true,state:"unavailable",available:false,error:...`; per-control capabilities govern disabled controls and unknown telemetry is null. UI asks for **manual device validation** rather than categorically denying recorded physical evidence. API `verified_4k:false` and build manifest false flags deliberately do not certify a human observation.
- `browse{path,offset,limit}`: root `""`, offset 0..4096, limit 1..200; returns path, entries `{name,path,type:file|directory,size_bytes:number|null}`, offset, more, scan_limited. Directory sizes are null. Byte-budgeted pages may be short: next offset is returned offset + **entries.length**. At scan limit narrow into subdirectories; entries are unsorted.
- `play{path}` accepts only library-relative allowlisted media; `pause{paused:bool}`, `stop{}`, `seek{seconds,relative:bool}` with finite ±31536000-second range/nonnegative absolute seek.
- `volume{value:0..100,mute?:bool}`; `tracks{type:audio|sub,id}` selects actual IDs 1..65535, 0 disables that type. mpv track metadata is not fabricated.
- `queue{action:list|append|clear|next,path?}`: memory-only, max128/64 KiB aggregate path bytes; list/append/clear return `entries:string[]`, next starts/removes head only on success and returns play acknowledgement. **No automatic advance**. Queue listing also requires write permission.
- `profile{name:quality4k|balanced|quiet}`: quality4k default loads paused and requires file-loaded/current-path/active hardware decoding before unpausing; independent watchdog handles hardware loss. Selecting it stops existing playback; play again. Failed stop IPC is an error, never “confirmed stopped.” Audio-only files cannot pass its hardware-video check. Balanced/quiet allow software diagnostics; quiet limits software threads to two.
Telemetry exposes **`dropped_frames` = decoder-frame-drop-count** and **`vo_dropped_frames` = frame-drop-count** separately, plus state/title/time/duration/tracks/codec/resolution/hwdec/volume/mute/A-V sync/profile/root/error. Zero decoder drops never proves zero presentation drops or smoothness.
### Daily use and profile selection
For H.264 1080p, VP9/AV1 software decoding or audio-only content, choose **Profile → `balanced`**, then Play the selected file. Balanced retains automatic hardware decoding where supported. Quiet also allows software with two decoder threads; it is not a promise of lower measured power. For the validated strict HEVC 4K30 path choose `quality4k` and press Play again; selecting it stops current playback.

Profiles/queue are in-memory controller state: a restart resets to `quality4k` and empties the queue. There is no automatic next-item advance or per-codec profile selection. Upload into the displayed directory using the file picker; refresh to verify a completed file before playing. Stop before deleting a played file, even after EOF. Uploads do not create directories and never replace existing names.

The profile at the time of the report was never read, so strict-profile rejection is the likely, unconfirmed explanation. See [troubleshooting](TROUBLESHOOTING.md).
## Security and production limits
### Media file management
The same LuCI page supports sequential multi-file uploads, per-file/batch progress, cancel, free/usable/reserved-space display and permanent per-file deletion after confirmation. Destination is the displayed library directory. It does not provide folder creation/removal, recursive deletion, rename or general filesystem management. Existing names are refused; delete explicitly or rename the source file before retrying.

`storage{}` is read-authorized; `remove{path}`, `upload_begin{path,size}` and `upload_cancel{token}` need media-write permission. Browse entries include `size_bytes`. The actual uhttpd session is injected into RPC calls and independently checked. Private `_upload_claim/_upload_check/_upload_done/_upload_abort` methods are never granted by the web ACL and reject HTTP-injected session metadata even if an ACL is mistakenly broad.

Binary data uses the native `/cgi-bin/airbridge-media-upload` on the existing server: fixed same-origin POST, raw `application/octet-stream`, nonempty chunks up to **1 MiB**, no query string. Authorization carries session, opaque capability and sequential byte offset in the header, never in URLs/logs. The CGI rechecks permission/ownership and held-file identity before reading any body bytes. It has bounded lifetime/body timeouts and modest per-worker priority; bulk writes and final file/directory synchronization happen outside the playback controller's event loop.

Partial files stay in owned mode-0700 `.airbridge-upload` on the media filesystem and are not browsable. Completed files publish atomically without overwrite only after declared-size/offset checks and file synchronization. Two concurrent upload slots, a **256 MiB safety reserve**, inactivity expiry and restart cleanup bound resource use. Cancellation removes partial data; a completed file may remain if the last acknowledgement was lost, so refresh before retrying. Canceled leased FDs are retained through worker acknowledgement/expiry to avoid descriptor-reuse races. Do not manually alter this private staging directory.

Writes require the actual configured dedicated ext4 mount, unchanged mount identity and safe held directory descriptors; root, boot, tmpfs, symlinks, hidden infrastructure and submount escapes are rejected. A missing media mount cannot redirect an upload into the small root filesystem. A held playback inode cannot be deleted until Stop; successful deletion prunes matching queue paths. Read-only sessions cannot upload/delete.

Use LuCI's raw-body callback: passing Blob directly would JSON-encode it on this installed version. Keep request `cache:true` solely to prevent LuCI adding a timestamp query string; CGI responses still have `Cache-Control:no-store`. uhttpd also requires a complete `Status: CODE REASON` header. R5 corrected that transport compatibility issue; JSON auth rejection had already prevented writes.

Validation includes 47 controller/file Python tests plus native protocol/mount/deadline/RPC tests and UI mocks. The [device record](../media/validation/file-management-20261114.json) records browser confirmation, real authenticated HTTP authorization/cancel/no-overwrite/delete checks and byte-for-byte SHA-256 verification of 8 MiB and 512 MiB generated uploads. During the larger transfer, 4K Main10 stayed on DRM decoding with no steady-state decoder/display drops; two startup display drops remain. >4 GiB declaration/cancel and UI-offset cases passed, but a complete >4 GiB transfer was not run. `media/tests/file_management_http.py` is an opt-in active device test with temporary scoped sessions and generated fixtures, never a routine build step or a reason to delete user files.

Player/controller still run as **root for hardware diagnostics**, not production least privilege. Move both to a shared dedicated UID only after real DRM/ALSA and `/proc` permissions are validated. Restrict management access; never expose raw mpv IPC over HTTP/network or broad ACLs.
Fixed argv/minimal environment, private libraries, umask077/runtime0700, singleton locks and bounded procd respawn reduce exposure. The controller opens its root read-only, traverses with `openat`/`O_NOFOLLOW`, rejects absolute/traversal/colon/backslash/control paths, accepts regular allowlisted files and passes retained `/proc/<pid>/fd/<fd>` handles against pathname races. Restart after replacing/remounting the library root. Administrator-created hardlinks/bind mounts inside it remain trusted.
Forced matching lavf demuxers prevent renamed playlist text from enabling playlists. Network protocols, scripts/plugins, user config search, external references, automatic subtitle/audio/cover files and resume writes are disabled. This is not a codec-parser sandbox, particularly under root. Logs/metadata may disclose media names; redact before sharing.

## Troubleshooting and recovery
Unavailable engine: distinguish disabled/new installation, missing object/private IPC, launcher/config/library failure and missing mount. Use targeted status/service outputs; do not weaken ACLs or install newer kernel dependencies. Absent hardware: verify exact modules/live DT/V4L2; fail-closed quality4k is intentional. No picture/sound: check connector/input, single DRM owner, ALSA mapping/TV mute; prior manual-bind trials are not instructions to perform sysfs writes.
For stutter, compare both decoder and VO counters over continuous samples; reducing GUI overlay overhead or tuning presentation requires fresh measured evidence, not a fallback relabeled as hardware success. Stop media writes on filesystem/GDT errors; do not rerun resize/repair/format or restore the pre-p3 MBR blindly.
Approved rollback is media-only: stop/disable the media service, restore known-good signed media packages/configuration and separately review the two activation startup entries. Do not unload in-use modules, remove shared dependencies or alter Wi-Fi/LCD to undo a media UI update. Boot KMS/CMA reversal requires comparing the private backup with later legitimate changes and coordinating reboot; do not restore an obsolete whole boot/root layout.
### Recovery boundaries
Persistent IPC monitors actual file-loaded/end-file errors and watchdog failures. A corrupt/unsupported file or hardware-loss error must stay visible; do not suppress it by fabricating playback state or switching policies without disclosure.
Root filesystem exhaustion and mount failure are storage incidents, not permission to remove unrelated packages or overwrite the only known-good recovery image.
