# Native media controller contract
Object: `airbridge.media`. No standalone HTTP server or raw player-command endpoint. LuCI uses authenticated rpcd ACLs; R4 adds one narrow native CGI on the existing uhttpd server. Every accepted ubus request returns a JSON object with `ok:boolean,error:string|null`; callers must inspect `ok` even when ubus transport succeeds.
## Methods
- `browse {path:"",offset:0,limit:100}`: relative path, root is `""`; optional offset 0..4096 and limit 1..200, integers. Returns `path,entries:[{name,path,type:"file"|"directory",size_bytes:number|null}],offset,more,scan_limited`. Directory sizes are null. Entries are filesystem order, not sorted; offset is the number of visible entries skipped. Output has a 192 KiB byte budget, so pages may contain fewer than limit entries; next offset is offset + entries.length. At most 4096 raw directory records scanned; when `scan_limited:true`, narrow into a subdirectory rather than repeatedly requesting later pages. Hidden entries, lost+found and unsupported files are omitted. No absolute paths are exposed.
- `play {path:string}`: local allowlisted file only. Success acknowledges load and (for quality4k) active hardware decoding, not successful HDMI presentation.
- `pause {paused:boolean}`, `stop {}`, `seek {seconds:number,relative:boolean}`: seek range ±31536000 seconds; absolute seek nonnegative.
- `volume {value:number,mute?:boolean}`: value 0..100 required; optional mute.
- `tracks {type:"audio"|"sub",id:integer}`: 1..65535 selects a player track; 0 disables that track type. Player rejection is an error, never simulated success.
- `queue {action:"list"|"append"|"clear"|"next",path?:string}`: append validates relative media path. List/append/clear return `entries:[string]` relative paths. Next starts and removes the first entry only on success. Maximum 128 entries and 64 KiB aggregate path bytes, memory-only. **No automatic advance**; explicit next only. Next returns the play acknowledgement.
- `profile {name:"quality4k"|"balanced"|"quiet"}`: default quality4k. Switching to quality4k stops the existing file; play again to run required-hardware initialization. Balanced and quiet explicitly permit software decoding for diagnostics; quiet caps libavcodec software threads at two, balanced leaves automatic threading. All profiles disable interpolation/deband. These are conservative controls, not measured thermal/performance promises.
- `status {}`: returns `available:boolean,state:"idle"|"playing"|"paused"|"unavailable",title,profile,error,time_pos,duration,volume,mute,track_list,codec,width,height,hwdec,dropped_frames,vo_dropped_frames,avsync,capabilities,media_root_available,verified_4k`.
Status unknown properties are **null**, not fabricated zeros. Track list is the actual mpv array (entries have id/type and optional title/lang/selected). `codec` is mpv video-codec, dropped_frames is decoder-frame-drop-count (not VO drops), avsync is the player-reported seconds. Title is the relative file basename, never the `/proc` path. `available` means private player IPC answered, not hardware readiness. Unavailable status is transport success with `ok:true`, `state:"unavailable"` and a descriptive error. `capabilities` has browse/play/pause/stop/seek/volume/mute/tracks/queue/profile booleans; controls are false when IPC is absent (browse remains true). `automatic_queue_advance:false,hardware_validation:false`; `verified_4k:false` is deliberate: this service cannot attest physical HDMI observation.
## R4 narrow file-management API
- `storage {}` returns `mounted,writable,upload,delete` booleans, `reason:string|null,total_bytes,free_bytes,usable_bytes,reserve_bytes:268435456,max_file_bytes,chunk_size:1048576,max_uploads:2,active_uploads`. Usable/max-file bytes subtract the reserve and pending uploads' remaining logical reservations; values are capped at the JavaScript-safe integer limit. Upload/delete flags describe backend readiness, **not user permission**. The UI must also respect its narrow write ACL.
- `upload_begin {path,size}` accepts an allowlisted relative media filename, existing same-mount parent and integer size **1..9007199254740991**, limited by actual usable space. It returns `token` (64 lowercase hex), `offset:0,size,chunk_size,max_size,expires_in:900,path`. Destination must not exist. No folder creation or replacement.
- `upload_cancel {token}` requires the same authenticated owner. It is idempotent: success returns `canceled:true` when pending work was canceled, false if already absent/canceled. Another session's capability is denied.
- `remove {path}` permanently removes only a regular allowlisted media file. No directories, symlinks, hidden infrastructure or cross-mount traversal. An inode still held for playback is refused with **Stop first**, including after EOF until Stop releases it. Matching queue paths are pruned on success. The entry is atomically claimed into private staging, compared against the opened inode before unlinking, and restored on a detected race; an un-restorable race/quarantine blocks writes for operator review instead of deleting an unknown entry.
Public mutation requests require a valid `ubus_rpc_session` supplied by authenticated uhttpd RPC; LuCI must **never** pass this argument itself. The controller independently asks session.access for the exact mutation method, accepting only a real boolean grant. Read ACL adds only storage; write ACL adds only upload_begin/upload_cancel/remove. No generic filesystem-write/exec/UCI/wildcard grants.
Status capabilities add `storage,remove,upload_begin,upload_cancel`. Storage/cancel remain supported without the playback engine; remove/begin reflect mount readiness, not caller ACL or playback busy state. The existing `dropped_frames` is decoder-frame-drop-count; R3 `vo_dropped_frames` is frame-drop-count. Neither file management nor its busy state changes the R3 player configuration/tuning.
### Binary CGI protocol
Fixed endpoint **POST `/cgi-bin/airbridge-media-upload`**, `Content-Type: application/octet-stream`, `Content-Length` **1..1048576**. No query string or PATH_INFO suffix. Credentials and offset travel only in the forwarded header:
`Authorization: Bearer <32-lowercase-hex-session>:<64-lowercase-hex-token>:<decimal-byte-offset>`
The third component is intentional: uhttpd does not forward arbitrary custom headers. Send sequential raw Blob slices, not JSON/multipart; never put credentials in URLs/logs. No zero-body finish call: the last nonempty chunk publishes the complete file.
Successful chunks return `ok:true,error:null,offset:<next-byte>,size:<total>,complete:boolean,path:<relative>`. Final CGI I/O fsyncs the file, then the backend publishes atomically **without overwrite**, then CGI fsyncs both target-parent and staging directories. Intermediate chunks do not fsync. Post-publication directory-sync failure is explicit (`ok:false,complete:true`, HTTP507); a completed filename is not rolled back or silently replaced.
The native helper validates session.access upload_begin permission **before body read**, obtains an owner/token-bound lease and opens only backend-held numeric `/proc/<pid>/fd/<fd>` paths. It checks device/inode, regular type, mode0600, nlink1, expected size/offset and an exclusive flock; another private check confirms staging identity and not canceled before stdin is consumed. Permission is checked again before completion. Bulk pwrite/fsync never runs in the controller event loop. CGI has at least nice10, 64 KiB buffers, 30-second body idle timeout and hard60-second process lifetime. Replies are JSON, Cache-Control:no-store/X-Content-Type-Options:nosniff, with no CORS headers.
On failed/disconnected chunks, cancel best-effort and stop the batch; already completed files remain. Do not silently retry a lost acknowledgement: publication may have completed. Refresh the library before starting another upload under that filename.
### Lease, mount and cleanup boundary
At most two slots exist. Token inactivity expires after900s; active writer leases after90s. Cancel unlinks partials immediately but **retains claimed file descriptors/inodes and parent descriptors** until worker acknowledgment or bounded lease expiry, preventing FD-number/inode reuse between claim and late CGI open. Workers can write an unlinked partial but cannot publish it. Canceled in-flight leases may temporarily count toward active_uploads until acknowledged/expired.
Private `_upload_claim`, `_upload_check`, `_upload_done`, `_upload_abort` are **not in rpcd web ACLs**. They use `session`, not ubus_rpc_session, and explicitly reject the latter's presence: uhttpd's mandatory injection therefore also prevents FD coordination through HTTP RPC even under an accidentally broad web grant.
Writable storage is conservatively limited to an actual **ext4 filesystem-root mountpoint** on a nonvirtual block device distinct from `/`, `/boot` and `/tmp`. Every mutation compares a fresh configured-root open with the held root's device/inode/mount ID and checks mountinfo/statvfs. Each opened parent must stay on that Linux statx mount ID, including rejection of same-device bind mounts. Missing/remounted media never falls back to root storage. Hidden components and lost+found are reserved.
Partials exist only in `.airbridge-upload` **on media**, directory0700/file0600, with an owned marker. No root/tmp spool. Startup removes only recognized owned regular mode0600/nlink1 partials. Unknown entries, symlinks, hardlinks and interrupted-delete quarantines are preserved and disable writes for operator review. The prototype still uses diagnostic root privileges, not a production least-privilege sandbox.
## Safety and engine prerequisites
Linux mpv >=0.38 (packaged engine 0.42), json-c, libubus/libubox. Engine `/usr/lib/airbridge-media/bin/mpv`, private libraries `/usr/lib/airbridge-media/lib`, fixed reviewed config `/etc/airbridge-media/mpv.conf`, IPC `/var/run/airbridge-media/mpv.sock`. Runtime directory 0700 and umask 077 protect the powerful private socket. Only the controller's typed API is exposed.
The pinned engine must be built with **`-Dlua=disabled -Djavascript=disabled -Dcplugins=disabled`**. Native launcher/package compile constants AIRBRIDGE_MEDIA_MPV_SCRIPTING=0 and AIRBRIDGE_MEDIA_MPV_LUA=0 match that build; script/ytdl/osc options are absent in such mpv builds and therefore deliberately not passed. If a separately reviewed engine enables any script processor, set SCRIPTING=1 to pass load-scripts=no/scripts=; if Lua is enabled, also set LUA=1 to pass ytdl=no/osc=no. Never pair scripting-enabled engine binaries with zero guards.
Installation is **disabled by default** (`enabled=0`). Both instances initially run as root solely as a temporary hardware-diagnostic privilege fallback because DRM/ALSA ACLs are unverified; this is not production least privilege. Move both to a shared dedicated UID after real device permissions are established. The native player launcher has fixed argv and a minimal execve environment; singleton flock locks and bounded procd respawn protect both instances.
Playback root is opened once with a read-only directory handle; restart after mounting a replacement root. Playback resolution remains openat/O_NOFOLLOW, regular files only, with no traversal, URLs, backslashes, colon, control characters, symlink or device files. File handles are retained and mpv loads `/proc/<controller-pid>/fd/<fd>`, avoiding pathname races. Linux `/proc` access and same UID player/controller are required. A read-only directory handle does not imply the filesystem itself is read-only: R4's separately authenticated file APIs provide the explicitly guarded write boundary above.
Allowlisted containers: mkv/webm, mp4/m4v/mov, avi, ts/m2ts, mpg/mpeg, mp3/flac/wav/ogg/opus/aac. The matching lavf demuxer format is forced, preventing playlist text renamed to a media suffix from activating a playlist demuxer. Player external references, scripts, user configs, ytdl and automatic external tracks are disabled. Engine should also be compiled without network protocols; package does not provide network media.
Required-hardware quality4k sets hwdec-software-fallback=no, loads paused, waits for the actual file-loaded event and checks loaded path and hwdec-current for up to four seconds, then unpauses only if active hardware decode is reported. It fails closed and requests stop otherwise; failed stop IPC is reported honestly, never presented as confirmed stopped. The 1-second daemon watchdog monitors hardware loss independently of UI polling. Persistent private IPC captures actual end-file error/file_error events for status.error. It does not force a particular kernel decoder backend, codec, resolution, refresh rate or HDMI connector; those remain acceptance checks on the actual pinned CM5 engine. Playback only tests the requested file; audio-only files cannot pass quality4k.
Playback IPC messages are capped at 64 KiB, requests at 8 KiB, each player IPC operation at 700 ms with 3-second per-call budgets (play/queue 6.5s). Ubus adapter reply cap is 256 KiB; calls are serialized. Session/CGI RPC transport workers bound even libubus object lookup to 1.3 seconds and terminate stale workers. Local filesystem metadata and uninterruptible kernel I/O remain subject to kernel/device behavior; bulk writes/fsync run outside the controller loop. Huge track metadata may become null/unsupported, not unbounded. Logs/metadata may disclose media names; do not expose private configuration or Authorization headers.
## Validation
`make -C media/controller check` runs playback fakeIPC regressions, generated-tempmedia/CGI tests, R4 package-metadata checks and native protocol/production-mount-policy/deadline assertions. Positive filesystem fixtures link a separately named fake mount provider; actual ACL request construction/boolean validation and CGI raw-body I/O run unchanged against fake RPC transport. A separate unit compiles actual upload_rpc.c/upload_auth.c against test-only transport headers to reject data-before-error status, missing object IDs, malformed grants and a hung lookup within its process deadline; this model is not a target ABI test. Release builds explicitly compile fs_mount.c/upload_rpc.c against real target headers, never host.c/tests/*.c or test-bypass flags. The native policy unit checks root/tmp/boot denial, exact mountinfo predicates and same-device/different-mount-ID rejection. Host json-c/pkg-config and Python standard library are needed; no Python/Node runtime is installed on device. Sanitizers may be supplied through CFLAGS/LDFLAGS. These tests do not validate actual uhttpd browser transport, Linux positive mount acceptance, hardware decoding/HDMI or 4K-under-upload performance; those remain separate lead/device acceptance.
